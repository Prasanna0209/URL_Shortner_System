# URL Shortener System

A production-style URL shortener system built with Java, Spring Boot, and MySQL. This system takes long URLs and converts them into short, unique links (similar to Bitly). It then seamlessly redirects users to the original URL when they visit the short link.

## Step 1: System Overview
### Architecture
- **Client**: A browser, mobile app, or Postman sending HTTP requests to the system.
- **API Layer (Controller)**: Receives HTTP requests (`POST /shorten`, `GET /{shortCode}`) and delegates the work to the Service layer.
- **Service Layer**: Contains the core business logic. It handles short code generation, ensuring uniqueness, saving to the database, and retrieving the original URL for redirection.
- **Database Layer**: Stores the URL mapping data using Spring Data JPA and MySQL.
- **URL Redirection Flow**:
  1. User visits `http://localhost:8080/abc123`.
  2. The `UrlController` intercepts the `GET` request.
  3. It calls the `UrlService` to find the original URL associated with `abc123`.
  4. If found, the click count is incremented, and the server returns an **HTTP 302 Found** response with the `Location` header set to the original URL.
  5. The client's browser automatically navigates to the original URL.

## Step 2: Project Setup
### Prerequisites

The project was created using Spring Boot dependencies:

- **Spring Data JPA**: To interact with the database using Hibernate.

## Step 3: Database Design
The application uses a table named `URL_MAPPING` which is automatically generated by Hibernate using property `spring.jpa.hibernate.ddl-auto=update`.

**Table Structure:**
- `id` (Primary Key): Unique identifier for each record.
- `original_url`: The long URL provided by the user.
- `short_code`: The unique 6-character string representing the short link.
- `created_at`: Timestamp recording when the short link was generated.
- `click_count`: Number of times the short link has been accessed.

**SQL Script (Reference executed by JPA under the hood):**
```sql
CREATE TABLE URL_MAPPING (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    original_url VARCHAR(2048) NOT NULL,
    short_code VARCHAR(10) NOT NULL UNIQUE,
    created_at DATETIME NOT NULL,
    click_count BIGINT NOT NULL DEFAULT 0
);
```

## Step 4: Entity Class
The `UrlMapping.java` class represents the `URL_MAPPING` table in Java using JPA annotations (`@Entity`, `@Table`, `@Id`, etc.).

## Step 5: Repository Layer
`UrlRepository.java` extends `JpaRepository`, providing built-in methods for database operations (like `save()`). It also includes a custom method `findByShortCode(String shortCode)` to quickly retrieve mapping records based on the short link code.

## Step 6: Short Code Generator
The `ShortCodeGenerator.java` utility generates a random 6-character string using the Base62 character set (`0-9`, `a-z`, `A-Z`). Base62 provides a vast number of unique combinations ($62^6 \approx 56.8$ billion), ensuring highly scalable unique short URLs while completely avoiding special characters that might break URLs.

## Step 7: Service Layer
`UrlService.java` orchestrates the logic:
- `createShortUrl()`: Generates a short code, verifies it does not already exist in the database, saves the new `UrlMapping`, and returns the short code.
- `getOriginalUrl()`: Fetches the `UrlMapping` by short code. If found, it increments the `clickCount` and returns the `original_url`.

## Step 8 & 9: Controller Layer and Redirection Flow
`UrlController.java` manages two main APIs:
1. `POST /shorten`: Accepts a long URL and returns the local short URL.
2. `GET /{shortCode}`: Takes the path variable `shortCode`, fetches the long URL, and issues an HTTP 302 redirect configuring the `Location` header.

## Step 10: Error Handling
`GlobalExceptionHandler.java` ensures the application fails gracefully by intercepting all unhandled exceptions (using `@ControllerAdvice`) and returning a well-formatted JSON response with an appropriate HTTP status code (e.g., `500 INTERNAL SERVER ERROR`). The Controller also handles invalid URLs and missing short codes by returning `400 Bad Request` or `404 Not Found`.

## Step 11: Testing using Postman
Here is how you can test the APIs using Postman:

### 1. Create a Short URL
- **Method**: `POST`
- **URL**: `http://localhost:8080/shorten`
- **Body** (Raw JSON):
  ```json
  {
      "url": "https://www.example.com/some/very/long/article/path"
  }
  ```
- **Expected Response** (200 OK):
  ```json
  {
      "shortUrl": "http://localhost:8080/aB3x9Z"
  }
  ```

### 2. Open Short URL / Redirection
- **Method**: `GET`
- **URL**: `http://localhost:8080/aB3x9Z`
- **Expected Response**: HTTP Status `302 Found` with HTTP headers redirecting you to `https://www.example.com/some/very/long/article/path`. Postman will automatically follow the redirect, so you will see the HTML of the target website inside Postman unless you disable \"Automatically follow redirects\" in Postman settings.

### 3. Invalid Request Example
- **Method**: `POST`
- **URL**: `http://localhost:8080/shorten`
- **Body** (Raw JSON):
  ```json
  {
      "url": ""
  }
  ```
- **Expected Response** (400 Bad Request):
  ```json
  {
      "error": "Invalid URL provided"
  }
  ```

## Step 12: Performance Optimization
For a high-scale production URL shortener, consider these enhancements:
1. **Database Indexing**: Add a unique index to the `short_code` column. In our JPA configuration (`@Column(unique = true)`), this index is already created out of the box, ensuring highly performant $O(1)$ or $O(\log n)$ database lookups.
2. **Caching (Redis/Memcached)**: Introduce a caching layer. Storing popular `{short_code: original_url}` mapping pairs in memory dramatically decreases latency, preventing repetitive SQL queries for heavily trafficked links.
3. **Optimized Link Generation (Zookeeper/Snowflake)**: Instead of generating codes randomly on each request and checking the Database for collisions, use a distributed offline key generation service. The service computes millions of standard short codes ahead of time, caching them into a queue to retrieve directly in $O(1)$ time whenever a user asks to shorten a URL.

## Step 13: GitHub Project Structure

Following standard Spring Boot and enterprise Java project organizational practices:

```text
src/main/java/com/example/urlshortener
│
├── controller/
│   └── UrlController.java           # Handles incoming HTTP requests and responses
│
├── service/
│   └── UrlService.java              # Core business and logic processing
│
├── repository/
│   └── UrlRepository.java           # Database interactions (Data Access Object)
│
├── model/
│   └── UrlMapping.java              # Database entity representing a table row
│
├── dto/
│   ├── ShortUrlRequest.java         # Data Transfer Object for incoming request bodies
│   └── ShortUrlResponse.java        # Data Transfer Object for outgoing response bodies
│
├── util/
│   └── ShortCodeGenerator.java      # Reusable helpers and utility logic used system-wide
│
├── exception/
│   └── GlobalExceptionHandler.java  # Custom exception handlers via ControllerAdvice
│
└── UrlShortenerApplication.java     # The absolute core main() Spring Boot Application entrypoint
```
The design patterns promote separation of concerns. Controllers shouldn't talk to repositories, everything passes through services which hold business constraints.

## Step 14: Setup Instructions
1. Ensure your MySQL server service is actively running on `localhost:3306`.
2. Connect to your MySQL workspace via CLI or an interface like MySQL Workbench and create a database named `url_shortener`.
   ```sql
   CREATE DATABASE url_shortener;
   ```
3. Update `src/main/resources/application.properties` with your existing MySQL `username` and `password` if they differ from the basic configurations (root/root).
4. Run the project from your IDE or by executing the following Maven wrapper command in the `D:\URL_Shortner_System` folder:
   ```bash
   mvn spring-boot:run
   ```
5. Test the REST endpoints using Postman using the payloads from Step 11 above!
